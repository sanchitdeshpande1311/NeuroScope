1. WHAT WAS WRONG WITH THE PREVIOUS GRAPH PAGE (audit)
=====================================================================
- The orange "nodes" were only one centroid per connected component of WT/TC/ET.
- The only edges were "contained in" links between components (ET→TC→WT), not spatial adjacency. Hence
  "scattered dots with a few disconnected-looking edges".
- The blue path was a voxel-level Dijkstra restricted to predicted-WT voxels, starting from the tumour core.
  It could never cross the non-tumour tissue between separate tumour components.
- Main visual cause: NiiVue's 3D tile volume-renders the T1Gd as an OPAQUE brain, so graph meshes inside the
  brain were hidden. Only meshes near the surface showed.
- Data source was correct: the graph was built from the current run's prediction. No stale, stored or expert
  data was used.

2. WHAT WAS BUILT
=====================================================================
A. ml/spatial_graph.py (new) - brain-wide lattice graph G = (V, E, W) from the CURRENT prediction + MRI brain mask
- Brain domain: non-zero voxels of the run's T1Gd OR FLAIR (skull-stripped inputs), holes filled. Tissue
  classes come only from seg.nii.gz (the model prediction). The expert mask is never read.
- Vertices:
  - Blocks of s_a = max(1, round(target_mm / spacing_a)) voxels (target 4 mm by default; 3 or 6 mm
    selectable). A block is kept if ≥ 50 % of it is brain or it contains predicted tumour.
  - Each vertex has: id; block-centre voxel coordinates; world mm (affine applied once); class = majority
    predicted label (0 non-tumour brain / 1 NCR/NET / 2 edema / 4 enhancing); label fractions; WT component;
    graph component; degree.
- Tumour components: 26-connected voxel-level WT components with volume, centroid and per-label volumes.
  Representative vertex = the component's vertex nearest its centroid.
- Edges: 26-neighbour block adjacency only (stored once, 13 half-offsets). No edges bridge gaps.
  - Length = ‖A[:3,:3]·(Δblock ⊙ s)‖ mm (anisotropy-aware).
  - Cost, Mode A = length.
  - Cost, Mode B (EXPERIMENTAL, hypothetical): length × (w_u + w_v)/2, w = 1 for tumour vertices and α
    (1-100) for non-tumour vertices. It encodes only a user-chosen preference for staying inside the
    predicted tumour; it is not a biological model.
- validate(): vertex references, self-loops, duplicates, finite positive lengths, finite non-negative costs,
  finite coordinates.
- stats(): V, E, connected components, largest component, isolated vertices, degree min/mean/max, vertices
  per class, method, block size, lattice spacing (mm), distinct edge lengths, build time.
- resolve(): v<id> | c<id> (component representative) | mm:x,y,z (nearest vertex + snap distance).
- shortest_path(): scipy.sparse.csgraph.dijkstra (non-negative costs) with predecessors. It returns:
  - the exact vertex sequence, points_mm, points_vox and vertex classes;
  - total cost plus the check cost_from_steps;
  - physical length and straight-line distance;
  - length per tissue class (each edge split half/half between its endpoint classes);
  - vertex and edge counts, and compute time;
  - "reachable: false" with the reason when the endpoints are in different graph components.
- render_subgraph(): tumour vertices, their 26-neighbour shell, and all real edges with at least one tumour
  endpoint (documented rule; no invented connections). lattice_arrays(): the full graph.

B. backend/main.py (modified)
- GET /api/runs/{id}/spatial-graph?target_mm= : provenance, stats, checks, components, drawn subgraph,
  default path between the two largest components, cost-mode descriptions, explanation text.
- GET /api/runs/{id}/spatial-graph/path?src=&dst=&mode=&alpha=&target_mm=
- GET /api/runs/{id}/spatial-graph/lattice?target_mm=  (full graph for the optional whole-brain layer)
- In-memory cache per (run, spacing), reused only if the SHA-256 of seg.nii.gz, t1c.nii.gz and t2f.nii.gz is
  unchanged; otherwise rebuilt. Evicted when a run is deleted. GraphBuildError → HTTP 422 graph_error.
- The earlier /api/runs/{id}/graph (voxel-level geodesic extent) is unchanged.

C. frontend/src/components/NiiVueViewer.tsx (modified)
- Overlay layers can now be tract ("lines") meshes. segmentsToTck() encodes 2-point segments as an MRtrix
  .tck buffer in the layout NiiVue's reader needs (leading NaN, NaN separators, Inf terminator, padding).
  It is loaded with NVMesh.loadFromUrl({buffer}) using fixed colour; radius > 0 gives thin cylinders so
  per-layer opacity works.
- Overlay sync is serialised (promise chain), so rapid toggles cannot duplicate layers.
- New hide3DVolume prop: in 3D-only mode the opaque volume rendering is hidden; in 4-panel mode the slices
  stay and occluded meshes use NiiVue's X-ray pass (0.35).
- Brain-surface opacity is now a setting (brainOpacity).

D. frontend/src/app/runs/[id]/graph/page.tsx (rewritten), lib/store.tsx (brainOpacity), globals.css (graph styles)
- Layers (each verified to change the image):

  - tumour edges (white) and boundary edges (light blue, off by default);
  - tumour surfaces and brain surface;

7. LIMITATIONS (honest)
=====================================================================
- Non-tumour brain is a single class. The project has no grey/white/CSF segmentation, so the path cannot
  report finer tissue types.
- Vertex classes are block majorities. Components smaller than a block do not become tumour-class vertices,
  but each still gets a representative vertex.
- Mode B weights are arbitrary user preferences, not biology. No growth or spread simulation is implemented
  (by design).
- A path describes connectivity of this graph only. It depends on the lattice spacing (±4 mm between
  spacings in the demo) and on prediction errors.
- The whole-brain lattice is drawn as 1-px lines (opacity fixed); dense views can clutter.
- Browser checks were scripted (DOM, renderer state and canvas pixels) in the Claude browser pane, mostly
  while the pane was hidden or narrow. Visual polish has not been reviewed by a human.
- Graph-page load is slow-ish (8-13 s) on this iGPU because many mesh layers are created.
