1. SUMMARY OF CHANGES
=====================================================================
This round made the existing app a multi-page website and added two backend features: a numerical
before/after refinement comparison, and interactive Dijkstra paths. The backend architecture, model,
preprocessing, inference and output format were kept.

ADDED
- Separate pages: Home, Upload & validation, Results, Full-screen 3D viewer, Graph analysis,
  Refinement before/after, Expert comparison, Report.
- Upload: four independent sequence slots (T1, T1Gd, T2, FLAIR) plus an optional expert-mask slot.
  - Each file is validated by the server as soon as it is chosen.
  - The set is then checked for a shared grid, with messages that name the incompatible sequences.
- Backend endpoints:
  - /api/validate-file, /api/validate-set
  - /api/runs/{id} (metadata + file list)
  - /api/runs/{id}/refinement
  - /api/runs/{id}/graph, /api/runs/{id}/graph/path
  - /api/evidence/refinement
- ml/refinement_compare.py: explicit before/after numbers.
  - Always: removed/added voxels, volumes, connected components.
  - With an expert mask only: TP/FP/FN, Dice, sensitivity, miss rate, FP share, % changes, and a
    rule-based verdict.
- ml/graph_analysis.GeodesicPathEngine: multi-source Dijkstra over the WT voxel graph that keeps
  predecessors, so each displayed path is exactly the computed one.
- Held-out evidence summary for the refinement: results/refinement_eval_summary.json.
- tests/test_ui_backend.py: 6 tests, including Dijkstra checked against an independent networkx computation.

FIXED (all found during this round's browser testing)
- NiiVue setMeshProperty forces a full volume refresh on every call, 8 times per control change.
  - A display change took 3.1-5.6 s → now median 107 ms, max 207 ms.
  - Viewer load 11.9 s → 4.0 s (hidden-pane measurements).
- Volume layer names without a file extension broke NiiVue loading.
- WebGL context released on a canvas that React then reused → shader-link failure. Each viewer now
  creates its own canvas.
- Disposed viewers kept drawing on released contexts (≈15,500 "blur/sobel shader" console errors).
  Now nv.cleanup() runs, and the context is released only after any in-flight load settles. 0 errors
  in the final check.
- Full-screen viewer: the page was 4 px taller than the window and the readout wrapped, so the canvas
  shifted after the first click and the second click landed 3 voxels off. Fixed with an exact-fit
  layout and a fixed-height readout; the crosshair error is now ≤ 1 voxel.
- NiiVue's built-in two-viewer sync needs canvas focus and did not fire. The refinement page now links
  its two viewers explicitly in world mm.
- Run files were served with no-store, so every page re-downloaded the MRI. Now "private,
  max-age=3600" (run files never change; well inside the 24 h retention). The PDF is served inline so
  it can be embedded.

REMOVED / REPLACED
- The single crowded page (frontend/src/app/page.tsx) was replaced by the Home page. Its functions moved
  to the new pages. The old file is in the backups.

UNCHANGED, ON PURPOSE

5. MATHEMATICAL REFINEMENT
=====================================================================
- Rule: remove WT connected components (26-connectivity) smaller than 10 mm^3 (seg_refined.nii.gz).
  Comparison only; never the primary output.
- Always shown, per region: before/after voxels and mL; Δ mL; Δ %; removed voxels; added voxels;
  % of before removed; components before → after; list of removed components (voxels, mm^3, centroid mm).
- With a validated expert mask (same run, same grid), for WT/TC/ET and before/after:
  - TP = pred ∧ ref, FP = pred ∧ ¬ref, FN = ¬pred ∧ ref.
  - Dice = 2TP/(2TP+FP+FN); 1.0 when both masks are empty.
  - Sensitivity = TP/(TP+FN); undefined when the expert region is empty.
  - Miss rate = FN/(TP+FN).
  - FP share = FP/(TP+FP). A background-denominator FP rate is deliberately not used.
  - % change of FP/FN uses the before count as the denominator; n/a when it is 0.
  - Volume error vs the expert, in mL.
  - Verdict per region: ΔDice > +0.001 improved, < −0.001 worse, else no meaningful change.
  - Overall verdict: Improved agreement / Worse agreement / Mixed result / No meaningful change.
    Computed, never hard-coded.
- Without an expert mask: only removed/added voxels, volume changes and components. The page states
  that removed voxels are not confirmed false positives, that a smaller volume is not automatically
  more accurate, and how to supply an expert mask.
- Evidence (30 patient-disjoint held-out cases, current code):
  - Mean ΔDice: WT +0.00079, TC 0, ET 0.
  - WT cases improved / worse / unchanged: 7 / 0 / 23.
  - WT voxel totals: FP 366,666 → 361,502 (−1.41 %); FN 274,042 → 274,069 (+0.01 %).
  - Overhead: 0.136 s per case.
  - Conclusion: NO MEANINGFUL CHANGE.
  - A unit test shows the rule can also delete real tumour (FN 0 → 2).
- Example run (5d16…, BraTS-GLI-00360-000 with expert mask): 9 WT voxels removed; FP 12,438 → 12,430;
  FN 4,063 → 4,064; Dice 0.9001 → 0.9001; verdict "No meaningful change".

6. GRAPH ANALYSIS AND DIJKSTRA
=====================================================================
- Component graph: nodes are the 26-connected components of WT, TC and ET (volume in mL, world-mm
  centroid). Edges mean "contained in" (ET → TC → WT). It is drawn as a NiiVue connectome at the real
  centroids.
- Dijkstra:
  - Graph: WT voxels, 26-neighbourhood, edge weight = physical distance between voxel centres in mm
    (uses the NIfTI spacing, so it is anisotropy-aware).
  - scipy.sparse.csgraph.dijkstra, multi-source from all TC voxels, min_only, return_predecessors.
  - Reported: geodesic extent max / p95 / mean, unreachable WT voxels, node and edge counts.
  - Destinations: the farthest reachable voxel overall and per WT component (actual Dijkstra maxima),
    or the WT voxel nearest the current crosshair.
  - The path is the predecessor chain from the target back to its nearest TC voxel, drawn through the
    exact voxel centres. Both length_mm (Dijkstra distance) and the sum of segment lengths are shown,
    and they match.
  - Verified against networkx multi-source Dijkstra (unit test with anisotropic spacing and a wall).
- Limitations:
  - Descriptive only: shortest paths through the predicted mask. It does NOT predict tumour growth or
    invasion.
  - Quality depends on the predicted mask.
  - WT voxels in components without TC are unreachable.
  - Graph build ≈ 4 s on first open (then cached; path queries ≈ 15 ms).
- Offline graph files: data/processed/graphs_v2 (deterministic, correct channel names). Deprecated
  graphs/ kept. Neither is used by inference.
